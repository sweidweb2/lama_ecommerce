================================================================================
                    LAMA ECOMMERCE - PRODUCT SUMMARY
================================================================================

PRODUCT NAME: Lama Ecommerce (AvioraWear)
PURPOSE: A full-featured, production-ready e-commerce platform built with 
         Next.js 16, TypeScript, and Supabase for managing online retail 
         operations with separate storefront, customer account, and admin 
         management interfaces.

================================================================================
                            CORE PURPOSE
================================================================================

This is a comprehensive e-commerce solution that enables businesses to:
- Sell products online through a public storefront
- Manage inventory, orders, and customers via an admin panel
- Provide customers with account management, order tracking, and wishlist features
- Handle complete order processing from cart to checkout to fulfillment

The platform is designed with security, scalability, and maintainability as 
core principles, using a layered architecture that separates concerns between 
UI, business logic, and data access.

================================================================================
                        HOW IT WORKS - ARCHITECTURE
================================================================================

LAYERED ARCHITECTURE:

1. PRESENTATION LAYER (app/ & components/)
   - Next.js App Router for routing and layouts
   - Server Components by default (for performance)
   - Client Components only when needed (state, effects, browser APIs)
   - UI components using Radix UI / shadcn-style components
   - Tailwind CSS for styling

2. BUSINESS LOGIC LAYER (services/)
   - Orchestrates use cases (create order, update product, apply discount)
   - Combines multiple repositories when needed
   - Contains authorization checks, validation, and domain rules
   - Never talks directly to Supabase

3. DATA ACCESS LAYER (repositories/)
   - Encapsulates all Supabase queries
   - One repository per aggregate/table
   - No business logic - only CRUD and query composition
   - Returns typed domain data

4. INFRASTRUCTURE LAYER (lib/)
   - Supabase client (server and client instances)
   - Auth helpers
   - Zod schemas for validation
   - Constants and utilities

5. STATE MANAGEMENT
   - TanStack React Query for async data fetching/caching
   - Zustand for client-only UI state (cart, wishlist, UI toggles)
   - Server state via React Query, client state via Zustand

6. DATABASE (Supabase PostgreSQL)
   - Row-Level Security (RLS) enabled on all tables
   - Database functions and triggers where needed
   - Proper indexes for performance
   - Foreign key constraints for data integrity

================================================================================
                        HOW IT WORKS - DATA FLOW
================================================================================

TYPICAL USER JOURNEY:

1. BROWSING PRODUCTS
   User → Storefront Page → Product Service → Product Repository → Supabase
   → Returns products → Displayed in UI

2. ADDING TO CART
   User clicks "Add to Cart" → Zustand Cart Store → Updates localStorage
   → Cart icon badge updates → Cart persists across sessions

3. CHECKOUT PROCESS
   User → Cart Page → Checkout Page → Address Selection → Shipping Method
   → Payment → Order Service → Order Repository → Supabase Transaction
   → Inventory Deduction → Order Created → Confirmation Page → Email Sent

4. ADMIN PRODUCT MANAGEMENT
   Admin → Admin Products Page → Product Service → Product Repository
   → Supabase → CRUD Operations → RLS Validates Admin Role → Changes Saved

5. ORDER FULFILLMENT
   Admin → Admin Orders Page → Order Service → Order Repository → Supabase
   → Update Order Status → Customer Sees Updated Status → Email Notification

================================================================================
                        SECURITY MODEL
================================================================================

THREE-LAYER SECURITY:

1. ROUTE PROTECTION (middleware.ts)
   - Validates JWT tokens
   - Checks user roles before allowing route access
   - Redirects unauthorized users

2. DATA PROTECTION (Supabase RLS)
   - Row-Level Security policies enforce data access at database level
   - Users can only access their own data
   - Admins can access all data (with proper policies)
   - Public data (products) accessible to everyone

3. BUSINESS RULE PROTECTION (Service Layer)
   - Additional authorization checks
   - Validation of business rules
   - Prevents invalid operations

ADDITIONAL SECURITY:
- Input validation with Zod schemas
- XSS prevention
- CSRF protection (Next.js built-in)
- SQL injection prevention (via Supabase parameterized queries)
- Payment data never stored (uses payment provider tokens)
- Environment variables for sensitive data

================================================================================
                        KEY DESIGN PRINCIPLES
================================================================================

1. SEPARATION OF CONCERNS
   - UI components have no business logic
   - Services orchestrate but don't access Supabase directly
   - Repositories handle all data access

2. TYPE SAFETY
   - TypeScript everywhere
   - Types inferred from Zod schemas
   - No `any` types

3. VALIDATION
   - Zod schemas for all inputs
   - Validation at multiple layers
   - Never trust client input

4. PERFORMANCE
   - Server Components by default
   - React Query for caching
   - Image optimization with Next.js Image
   - Lazy loading for heavy components

5. ACCESSIBILITY
   - Keyboard navigation support
   - ARIA labels where needed
   - Responsive design

6. MAINTAINABILITY
   - Small, focused modules
   - Clear naming conventions
   - Consistent patterns throughout
   - Comprehensive documentation
